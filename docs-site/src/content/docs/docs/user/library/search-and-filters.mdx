Cove’s list pages are designed so you can narrow a large library quickly without relearning the controls on every content type.

## What to use first

Most of the time, start in this order:

1. Choose the content page you want.
2. Use search to narrow by the thing you remember.
3. Apply filters when the result is still too broad.
4. Save the view if you know you will come back to it.

## What search is for

Search is best when you already know something concrete:

- part of a title
- a performer
- a tag
- a studio
- a group or other meaningful metadata

Search is how you find likely candidates quickly.

## What filters are for

Filters are best when you want to shape a result set deliberately:

- only one content type or orientation
- only items missing metadata
- only items with a specific rating or state
- only items that match a recurring review workflow

Filters are how you turn “somewhere in the library” into “the exact slice I want right now.”

### Remote ID filters

Videos, performers, studios, and tags provide a **Remote ID** filter. Enter the external identifier and optionally select one of Cove's configured metadata services. **Any metadata service** searches identifiers across every endpoint. Cove stores the endpoint separately from the identifier, and a saved filter that refers to a removed service shows its endpoint as an unconfigured selection until you choose another service.

**Equals**, **Includes**, and **Regex** match identifier values without regard to letter case. Their inverse operators also include records that have no matching remote ID. With **Any metadata service**, **Is Null** and **Not Null** check whether the record has any remote ID. When a service is selected, those null checks are scoped to that service. **Remote ID Count** continues to filter the total number of remote IDs.

## Saved filters and recurring views

If you use the same search and filter combination more than once, save it. A [saved filter](../../../reference/saved-filters/) preserves per-user query state and reevaluates it against the current library. Typical saved views include:

- cleanup queues
- “missing metadata” work lists
- favorite performers or studios
- tag-based watch queues
- smart “come back later” collections

Saved filters often become the bridge between one-off searching and [dynamic groups](../../../reference/dynamic-groups/), which have a library record and changing resolved membership.

## View modes and page size

Search and filters work alongside the rest of the list-page controls:

- sort order
- view mode
- page size
- feed or vertical-style browsing

That matters because a useful result set is not only about what is included. It is also about how you plan to move through it next.
