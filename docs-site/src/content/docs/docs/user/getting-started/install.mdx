title: Install

Cove runs on your own machine. Choose the native app for a managed local installation, or Docker when you already operate containers on a server or NAS.

Downloads and release notes are on the [latest release page](https://github.com/yourcove/cove/releases/latest).

## Native app

1. Download the package for Windows, macOS, or Linux from the [latest release](https://github.com/yourcove/cove/releases/latest).
2. Install and start Cove. The app prepares its database and opens Cove in your browser.
3. In the first-run setup wizard, choose **Start Fresh**, **Import from Stash**, or **Restore Cove Backup**.
4. Create the owner account when prompted.

The native app includes Cove Instance Manager. Each instance has its own home directory, database, configuration, generated assets, backups, and logs. Use the manager to create, start, stop, or switch instances rather than sharing one data directory between them.

## Docker: all in one

The all-in-one image runs Cove, PostgreSQL, pgvector, and FFmpeg in one container, so you operate one application container instead of separate Cove and database containers.

1. Install Docker Engine with the Compose plugin.
2. Download [`docker-compose.allinone.yml`](https://github.com/yourcove/cove/blob/main/docker/docker-compose.allinone.yml) from Cove's `docker/` directory and work from the directory containing that file.
3. Choose a host directory for Cove's persistent data. The compose file uses `./cove-data` by default; set `COVE_DATA_DIR` to keep it elsewhere.
4. Edit the media-volume example in the compose file so the host path points to your library:

   ```yaml
   volumes:
     - /srv/media:/media:ro
   ```

   `/srv/media` is an example host path. `/media` is the path Cove can see and is the path you will enter during setup. Keep source media read-only unless another workflow specifically requires write access.
5. Start Cove:

   ```bash
   COVE_DATA_DIR=/srv/cove docker compose --file docker-compose.allinone.yml up --detach
   COVE_DATA_DIR=/srv/cove docker compose --file docker-compose.allinone.yml ps
   ```

6. On the Docker host, open `http://localhost:5073`. From another machine on the same network, replace `localhost` with the Docker host's address.

The provided compose file persists these paths:

| Container path | Default host location | Contents |
| --- | --- | --- |
| `/var/lib/postgresql/cove-data` | `${COVE_DATA_DIR}/pgdata` | PostgreSQL database |
| `/config` | `${COVE_DATA_DIR}/config` | `cove-config.json`, installed extensions, and logs |
| `/generated` | `${COVE_DATA_DIR}/generated` | Covers, thumbnails, previews, and other derived assets |
| `/backups` | `${COVE_DATA_DIR}/backups` | Database and config backups |
| `/media` | The host path you add | Source media, mounted read-only in the example |

Do not remove the database, config, generated, or backups mounts when customizing the compose file. The named cache volume is disposable and can be regenerated.

## Docker: separate app and database

Use [`docker-compose.yml`](https://github.com/yourcove/cove/blob/main/docker/docker-compose.yml) when you want Cove and PostgreSQL in separate containers. Edit the same media-volume example, choose `COVE_DATA_DIR`, and start it from the directory containing the file:

```bash
COVE_DATA_DIR=/srv/cove docker compose --file docker-compose.yml up --detach
COVE_DATA_DIR=/srv/cove docker compose --file docker-compose.yml ps
```

The app is still available at `http://localhost:5073`. The compose file provides the internal database connection and persists PostgreSQL under `${COVE_DATA_DIR}/pgdata`. If you change the database credentials, update both the PostgreSQL service and Cove's connection string so they continue to match.

## Complete first-run setup

For a new library, choose **Start Fresh**, enter one or more paths that Cove can see, review them, and select **Save & Continue**. In Docker, use container paths such as `/media`, not host paths such as `/srv/media`.

After setup, follow [First scan](../first-scan/) to run, monitor, and verify the initial scan. The owner can later change library paths, create users and roles, create API tokens, and configure providers, downloaders, and extensions.

## Run from source

If you want to inspect or modify Cove itself, see [Run Cove locally](../../../developer/getting-started/local-development/). A source checkout is a development workflow, not the recommended production installation.

## Expose Cove outside your network

Cove includes users, roles, permissions, share links, API tokens, audit history, and content rules. If you make it reachable from the internet, put it behind a reverse proxy, enable TLS, keep Cove current, and treat it like any other self-hosted service that can reach private media.
