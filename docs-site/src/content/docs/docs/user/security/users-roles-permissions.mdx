Cove is built to support more than one person using the same library. That means access needs to be deliberate instead of collapsing into one shared login with full control over everything.

## The access model

- **Users** are the people or service identities signing in.
- **Role assignments** connect users to roles.
- **Roles** bundle reusable action permissions.
- **Content rules** can grant scoped read access and restrict read, write, or delete access for matching records.
- **Share links** let you expose selected content within your network without creating a full account.
- **API tokens** let scripts or integrations authenticate without reusing a password.

These pieces are strongest when used together, not in isolation.

## A practical setup order

1. Keep the owner account protected and use it sparingly.
2. Create separate user accounts for real people.
3. Define roles around actual responsibilities.
4. Add content rules when access to content should differ between people.
5. Use share links for narrow access within your network instead of broad logins.

## Roles versus content rules

This distinction is important:

- **roles** grant general action permissions to an account
- **read-scoped allow rules** can grant access to matching records even without the corresponding role read permission
- **write and delete content rules** require the corresponding role permission and can only narrow the records on which those actions are allowed

A read-scoped allow rule can expose a specific slice of the library to a role that lacks general read permission for that entity kind. For edits or deletion, the role must already have the relevant permission; a content rule can limit where it applies but cannot grant it. An explicit entity deny wins over everything; otherwise, an explicit entity allow wins; among matching content rules, any allow wins over matching denies.

## Share links

Share links are useful when you want to expose specific content within your network without turning a temporary need into a full new account. They are a better fit when:

- the access is narrow
- the access is time-limited
- the person does not need normal library navigation

## Internet exposure

If you expose Cove outside your local network, treat it like any self-hosted application that can access private media:

- put it behind your own reverse proxy and TLS
- avoid exposing administrator accounts directly
- review roles and share links carefully
- assume the security model is only as strong as the way you publish the service
