title: Frontend runtime API

Cove loads extension frontend bundles as ESM and provides a versioned set of host modules. Import from this runtime instead of bundling another copy of React or reaching into Cove's internal source tree.

The current runtime contract is `v1`. Cove supplies that value in the aggregated UI manifest; `UIManifestBuilder.WithRuntimeVersion` does not select a different runtime. Treat every import not listed on this page as private implementation detail.

## Runtime modules

Use the `@cove/runtime/*` specifiers in extension source:

| Module | Provides |
| --- | --- |
| `@cove/runtime/react` | React |
| `@cove/runtime/react-dom` | React DOM |
| `@cove/runtime/react-dom-client` | React DOM client APIs |
| `@cove/runtime/react-jsx-runtime` | Production JSX runtime |
| `@cove/runtime/react-jsx-dev-runtime` | Development JSX runtime |
| `@cove/runtime/react-query` | TanStack Query |
| `@cove/runtime/lucide-react` | Lucide React icons |
| `@cove/runtime/components` | Cove's public shared component and hook barrel |
| `@cove/runtime/api` | Authenticated requests to Cove APIs |
| `@cove/runtime/webxr` | Immersive (WebXR) playback of VR videos |

Cove still maps the corresponding bare third-party specifiers for older bundles, but new bundles should use the namespaced runtime imports. Configure the extension build to leave runtime modules external so Cove and the extension share the same React tree and host libraries.

## Immersive VR playback

`@cove/runtime/webxr` is the same WebXR playback the video player's **Enter VR** button uses, so an
extension that shows VR videos plays them exactly as Cove does. VR videos carry their layout in
`video.vr` (`projection`, `fieldOfView`, `stereoMode`); it is `null` for flat videos.

```tsx
import { getImmersiveVrSupport, startImmersiveVideo } from "@cove/runtime/webxr";

// From a click handler: requesting an immersive session needs a user gesture.
if ((await getImmersiveVrSupport()).supported) {
  await startImmersiveVideo(videoElement, video.vr, { onEnd: () => setInVr(false) });
}
```

An extension that opens its own session (a 3D gallery, say) requests it with `immersiveSessionInit()`
so media layers are available, then hands a video off with
`playVideoInSession(session, videoElement, video.vr, { onExit })`. The video replaces the session's
layers until the viewer presses B/Y, then the previous layers are restored and `onExit` runs. Pause
your own rendering meanwhile (with three.js, `renderer.setAnimationLoop(null)`).

To open a video's page in the browser while the headset keeps the session, hand the session over instead:
`offerSessionHandoff(session, { onReturn })`, then navigate to the video (`onNavigate({ page: "video", id })`).
The page's player claims the session and plays into it; when the viewer presses back (B or the stick click) it restores the
session's previous layers and calls `onReturn("exit")`, where the extension resumes rendering and navigates
back. If the browser leaves the video's page instead, the player returns the session with `"abandoned"`:
resume rendering, but leave the browser where it is.
An offer nobody claims (the page had no VR player) times out into `onTimeout`.

Lend your renderer with the offer's `presenter` (your XR-compatible WebGL 2 context, the layer that is the
session's base layer, your reference space, and a `setFrameRenderer` slot you call from inside your own XR
animation frame, resetting your GL state afterwards). The player then draws into your layer from your
loop and never touches the session's render state. Without a presenter the player installs its own base
layer and frame loop, which leaves a three.js loop that is still running against a layer that is no
longer the base layer, and that loop does not survive it.

`playVideoInSession` accepts a `transport` (`currentTime`, `duration`, `seek`) for players whose element
does not hold the whole video, such as a transcode, and an `element` getter for players that replace
their element mid-playback. Use
`requestImmersiveSession()` rather than `navigator.xr.requestSession` so a session the page still has
is ended first; a second concurrent request otherwise fails or hangs on desktop OpenXR.

WebXR needs a secure context. `localhost` qualifies; a headset reaching Cove by LAN address needs
Cove's HTTPS listener (`Cove:HttpsPort`). `getImmersiveVrSupport()` reports
`reason: "insecure-context"` when that is what is missing.

## Authenticated API requests

Import `extensionFetch` from the API module:

```tsx
import { extensionFetch } from "@cove/runtime/api";

export async function loadSummary() {
  const response = await extensionFetch("/api/ext/com.example.reports/summary");
  if (!response.ok) {
    throw new Error(`Request failed with ${response.status}`);
  }

  return response.json();
}
```

Its signature is:

```ts
interface ExtensionFetchOptions extends RequestInit {
  timeoutMs?: number | null;
}

function extensionFetch(input: string, init?: ExtensionFetchOptions): Promise<Response>;
```

`extensionFetch` accepts only same-origin URLs whose path is `/api` or starts with `/api/`. Relative forms such as `api/ext/...` are normalized against the current Cove origin. Cross-origin URLs and non-API paths throw a `TypeError` before a request is sent.

Extension requests do not time out by default, preserving normal `fetch` behavior for long-running extension operations. Set `timeoutMs` to a positive number to opt an individual request into a timeout. Passing `null` or omitting the option leaves the request unlimited; a caller-provided `AbortSignal` can still cancel it.

The helper sends the current bearer or share credentials, uses Cove's normal access-token refresh and single retry behavior, and returns the standard `Response`. It forces `redirect: "error"` so an API request cannot follow a redirect outside the allowed boundary.

Authentication transport does not grant access. Protect the extension endpoint with the appropriate server-side convention from [Extension permissions](../permissions/), and handle expected `401`, `403`, and application errors in the component.

Import public UI building blocks from one barrel:

import {

  DetailListToolbar,

  RelatedEntityListView,

### Native detail layout

`MediaDetailLayout` gives extension pages the same responsive shell used by Cove detail pages. Its required `title` prop accepts a React node. Optional props cover:

- navigation with `backLabel` and `onGoBack`
- the media region, its aspect ratio and position, sticky behavior, and full-bleed rendering
- a header image, actions, and engagement controls; without engagement controls, the actions sit on the subtitle's line
- an `eyebrow` label above the title saying what kind of page it is, and `headerDetails`, a line of short facts shown right under the subtitle
- sidebar or header tabs with an active key and change callback
- keyboard shortcuts, loading state, errors, and child content

`MediaDetailTab` describes each tab with a stable `key`, `label`, and optional icon, count, disabled state, and manual contexts. `MediaDetailSectionProps` is the small typed wrapper contract for section children and an optional class name.

### Native detail lists

`DetailListToolbar` composes Cove's result count, search, sorting, filter dialog, saved filters, selection controls, display modes, zoom, and paging controls around a `FindFilter`. Supply only the capabilities the embedded list supports; the required props are `filter`, `onFilterChange`, `totalCount`, and `sortOptions`.

Use `DetailListPagination` when the pager belongs below the results instead of inside the toolbar:

```tsx
<DetailListPagination
  filter={filter}
  onFilterChange={setFilter}
  totalCount={totalCount}
/>
```

It also accepts `allowInfinitePageSize`, `infinitePageSizeOnly`, `showPagingControls`, `className`,
and `ariaLabel`. Give top and bottom pagers distinct `ariaLabel` values. Once a non-empty count is
known, the paginator corrects an out-of-range `filter.page` through `onFilterChange`; it does not
reset a deep page while the count is zero or still loading. The pager inside `DetailListToolbar`
uses `Pagination above results` by default and can be renamed with `paginationAriaLabel`.

These primitives provide Cove's current UI behavior, but the extension still owns its data query, empty and error states, and permission handling. Prefer host CSS variables and shared components over copying internal markup or Tailwind classes that are not part of this barrel.

### Preference-aware narrative text

Use `NarrativeText` for descriptions, biographies, notes, and other narrative metadata that should follow the viewer's Interface preference:

```tsx
import { NarrativeText } from "@cove/runtime/components";

export function Summary({ details }: { details: string }) {
  return <NarrativeText className="text-sm leading-6 text-secondary">{details}</NarrativeText>;
}
```

The component renders literal whitespace-preserving text by default. When the user enables Markdown rendering, it applies Cove's safe textual Markdown rules and theme-aware styles. Raw HTML and images are not rendered. Safe links open in a new tab. Use `useMarkdownRenderingEnabled()` only when surrounding extension UI must also change; prefer `NarrativeText` when only the text rendering differs.

### Browser title

A page an extension contributes is titled with its label, such as "Segment Studio | Cove". Call `useDocumentTitle` to name the view more specifically; on the extension's page the title goes in front of the label:

```tsx
import { useDocumentTitle } from "@cove/runtime/components";

export function Editor({ video }: { video: { title: string } }) {
  useDocumentTitle(video.title); // "<video title> | Segment Studio | Cove"
  return null;
}
```

The title applies while the component is mounted. When several components set one, the innermost wins, and between siblings the one mounted last. An empty title, or `false` as the second argument, leaves the title to the enclosing page. Outside the extension's own pages, such as in a tab on a video's page, the call replaces that page's title rather than adding to it. The hook is new in Cove 1.6, so an extension that supports older versions should look it up on the module namespace (`import * as components from "@cove/runtime/components"`) instead of importing it by name, which would stop the bundle loading on those versions.

### Video queue

`useVideoQueue` gives a component Cove's video queue: the list behind the video page's queue panel, the player's previous and next controls and the <kbd>[</kbd> and <kbd>]</kbd> keys. Setting the queue takes effect at once, without a page load, and Cove keeps it for the browser tab across reloads.

```tsx
import * as components from "@cove/runtime/components";

const useVideoQueue = components.useVideoQueue ?? (() => null);

export function PlayAll({ videos }: { videos: { id: number; title: string; status: string }[] }) {
  const queue = useVideoQueue();
  if (!queue || videos.length === 0) return null;

  const open = () => {
    queue.setQueue(
      videos.map((video) => video.id),
      videos[0].id,
      videos.map((video) => ({ id: video.id, title: video.title, subtitle: video.status })),
      { source: "my-extension:review" },
    );
    components.navigateToUrl(`/video/${videos[0].id}`);
  };

  return <button onClick={open}>Play all</button>;
}
```

The hook returns a `VideoQueueHandle`:

| Member | Description |
| --- | --- |
| `queue` | `null` without a queue, otherwise a `VideoQueueSummary`: `videoIds`, the videos the queue has loaded in play order, and `source`, the label it was opened with. A queue Cove opened from a paged list loads further videos as playback reaches them, so `videoIds` can grow. |
| `currentId` | The queue's current video, or `null` without a queue. On a video's page it can differ from the video shown when that video is not in the queue. |
| `autoplay` | Whether the next video starts when one ends; `false` without a queue. |
| `setQueue(ids, currentId, items?, options?)` | Replaces the queue. `currentId` falls back to the first video when it is not in `ids`, and an empty `ids` clears the queue. `items` are `VideoQueueItem` values for the queue panel: `id`, `title`, `subtitle` and `imagePath`, the URL of the image to show. A video without an item shows its id only. `options.autoplay` left out starts the queue with the user's **Auto-advance to the next item in a list** setting, as the queues Cove opens do; pass `autoplay` from the handle to keep the current choice. `options.source` labels the queue. Setting the queue does not navigate; open the video afterwards. |
| `updateItems(items)` | Changes how videos already in the queue are shown, for example a subtitle that carries a status. In each item a field left out keeps what the queue shows and `null` clears it, so `{ id, subtitle }` changes the subtitle alone. The queue's videos, order, position and autoplay stay as they are, and items for videos that are not queued are ignored. Use it instead of `setQueue` for a queue the extension did not open, because replacing a queue Cove opened from a paged list stops that queue loading further pages. The panel shows "Now playing" in place of the current video's subtitle. |
| `clearQueue()` | Removes the queue. |

Give each queue the extension opens a `source` that starts with the extension's id, and compare `queue.source` later to tell whether the queue is still that one. Any queue opened without a source, including every queue Cove opens itself, has none. The handle is a new object whenever the queue, its current video or autoplay changes, but `setQueue`, `updateItems` and `clearQueue` keep their identity. An effect that calls one of them must depend on that function, never on the handle or on `queue`: every `setQueue` produces a new `queue` and handle, so such an effect would run without end.

Cove 1.8.0 and earlier do not have the hook. An extension that supports those versions should look it up on the module namespace as above, because importing it by name would stop the bundle loading on those versions. It returns `null` when rendered outside Cove's queue provider, so treat `null` and a missing export alike: do without the queue, for example by offering a plain link to the video. Contributions to `APP_FLOATING_UI_SLOT` are inside the provider on every version that has the hook.

### Reusable video player controls

`VideoPlayer` can register bounded controls for a component that renders the reusable player:

```tsx
<VideoPlayer
  {...playerProps}
  onSeekRegister={(seek) => {
    seekRef.current = seek;
  }}
  onPlaybackControlRegister={(controls) => {
    controlsRef.current = controls;
    return () => {
      controlsRef.current = null;
    };
  }}
/>
```

`VideoPlayerSeek(time, forcePlay?)` keeps the historical play-on-seek behavior by default. Pass
`false` to preserve the current playing or paused state. `VideoPlayerPlaybackControls` provides
`play`, `pause`, `toggle`, and relative `seekBy`; relative seeks also preserve playback state.
`play` returns a promise because browser playback policy can reject it. A registration callback may
return cleanup, which Cove runs before replacing that control generation and when the player
unmounts. These controls operate the reusable `VideoPlayer`; media-player slot contributions should
use the bounded controls in `MediaPlayerExtensionContext`.

## Compatibility

Runtime modules are a host contract, not dependencies embedded in the extension archive. Set `minCoveVersion` to the oldest Cove release on which every imported runtime export has been tested. Adding an import introduced by a newer Cove release raises that practical compatibility floor even when the extension's backend contract is unchanged.

An extension can use a newer export without raising its floor by importing the barrel as a namespace (`import * as components from "@cove/runtime/components"`) and checking that the export exists before using it. A named import of an export the host lacks stops the whole bundle loading. `EntityMedia`, `useDocumentTitle` (new in Cove 1.6) and `useVideoQueue` (not in Cove 1.8.0 or earlier) are exports to detect this way; `useVideoQueue` additionally returns `null` outside Cove's queue provider, so one fallback covers both cases. Members added later to an object a hook returns, such as `VideoQueueHandle`, need the same check.

Keep a package's frontend imports and its declared compatibility floor in sync, then test installation and the rendered contribution on that minimum version. See [Package an extension](../packaging/) for how installers enforce `minCoveVersion` and [UI extension points](../ui-extension-points/) for where components can be mounted.
